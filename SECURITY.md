# Security Policy

We take the security of our software and data very seriously. If you discover a security vulnerability, we appreciate your help in disclosing it to us responsibly.

---

## 🚨 Supported Versions

The following table indicates which versions of our project are currently being supported with security updates:

| Version          | Supported              |
| :--------------- | :--------------------- |
| `1.x.x` (Latest) | :white_check_mark: Yes |
| `< 1.0`          | :x: No                 |

---

## 🔍 Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.** Doing so may put the user community at risk before a fix is available.

- **Primary Contact:** Please report vulnerabilities via email at **`your-security-email@example.com`**.
- **Response Time:** We will do our best to respond within **48 hours** to acknowledge receipt of your report.

### What to Include in Your Report:

To help us triage and reproduce the issue quickly, please include:

1. **Type of vulnerability** (e.g., SQL Injection, XSS, Remote Code Execution, etc.).
2. **Step-by-step instructions** to reproduce the issue, including code snippets or a Proof of Concept (PoC) if applicable.
3. **Potential impact** and what an attacker could achieve.

---

## 🛡️ Disclosure Policy

1. Our team will review the report and verify the vulnerability.
2. We will work with you to test and develop a proper patch/fix.
3. Once the patch is released, we will publicly credit you in our release notes or security advisories (unless you prefer to remain anonymous).

---

Thank you for helping keep our project safe and secure!
